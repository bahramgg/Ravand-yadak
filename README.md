# روند یدک — فروشگاه لوازم و قطعات یدکی خودرو

سایت استاتیک، راست‌چین و بدون وابستگی به CDN. از کلون یک طرح مرجع شروع شد و سپس با هیروی
تمام‌صفحه‌ی سه‌بعدی، جستجوی قطعه و تصاویر تولیدشده با هوش مصنوعی بازطراحی شد.

## اجرا

```bash
cd yadak
python -m http.server 4310 --bind 127.0.0.1
# سپس: http://127.0.0.1:4310/index.html
```

فایل `index.html` مستقیم با دابل‌کلیک هم باز می‌شود (همه چیز محلی است).

## ساختار

```
yadak/
├─ index.html                 صفحه اصلی
├─ assets/
│  ├─ css/style.css           تمام استایل‌ها + بریک‌پوینت‌های واکنش‌گرا
│  ├─ js/main.js              کاتالوگ محصولات، جستجوی قطعه، دکمه بالا، منوی موبایل
│  ├─ js/hero-fx.js           دوربین سه‌بعدی هیرو + باران، دود اگزوز، بازتاب، رعد
│  ├─ fonts/peyda-*.woff2     پیدا با ارقام فارسی (۱۰۰ تا ۹۰۰) — محلی
│  └─ img/
│     ├─ logo-mark.svg, samandehi.svg
│     ├─ hero/plate.jpg, hero/car.png   لایه‌های عمق هیرو
│     ├─ products/p1..p10.png  عکس محصولات با پس‌زمینه شفاف
│     ├─ banners/              هیرو، موتور، کابین، بنر تخفیف، بنر درخواست قطعه، برش خودرو
│     └─ blog/blog1..3.jpg
└─ tools/                     اسکریپت‌های پایتون تهیه و پاک‌سازی عکس‌ها
```

## بخش‌های صفحه

هدر (لوگو، جستجو با انتخاب دسته‌بندی، آیکون‌های کاربر/علاقه‌مندی/سبد) ← منوی اصلی + دکمه
«درخواست قطعه» ← هیرو متحرک (بنر بزرگ بدنه + بنر موتور + بنر کابین) ← شش آیکون دسته‌بندی ←
جدیدترین محصولات (۵×۲) ← **نوار جستجوی قطعه** ← پیشنهادات ویژه با تصویر برش خودرو ←
بنر «ثبت فوری درخواست قطعه» ← مجله ی آموزشی ← نوار مزیت‌ها ← فوتر.

## تهیه عکس‌ها

عکس‌ها با اسکریپت‌های `tools/` از منابع عمومی گرفته و پس‌زمینه‌شان با flood-fill و
white-key حذف شده است. برای گرفتن دوباره:

```bash
cd tools
python run_fetch.py        # همه دارایی‌ها (فایل موجود را دست نمی‌زند)
python compose_cta.py      # ساخت بنر «درخواست قطعه» از قطعات جدا شده
python sheet.py            # کنتکت‌شیت برای بازبینی چشمی
```

برای جایگزینی هر عکس کافی است فایل هم‌نام را در `assets/img/` عوض کنید؛ نیازی به
تغییر کد نیست.

## نکته‌ها

- کاتالوگ محصولات در بالای `assets/js/main.js` (شیء `P`) تعریف شده؛ نام، قیمت،
  قیمت قبلی، درصد تخفیف و نیز `cat` / `part` / `sku` / `tags` که جستجو روی آن‌ها کار می‌کند.
- قیمت‌ها با ارقام فارسی و جداکننده هزارگان رندر می‌شوند.
- لینک‌های منو و محصولات فعلاً `#` هستند — طرح مرجع فقط صفحه اصلی را نشان می‌دهد.

## جستجوی قطعه

نوار تیره‌ی میانی صفحه یک جستجوی کامل سمت‌کاربر است:

- فیلتر زنده روی نام، نام قطعه، دسته‌بندی، برچسب‌ها و شماره فنی
- ارقام فارسی/عربی و «ی/ک» عربی یکدست می‌شوند؛ تایپ `۳` و `3` هر دو یک نتیجه می‌دهند
- فیلتر دسته‌بندی، چیپ‌های جستجوی پرطرفدار، و هایلایت عبارت در نتایج
- کیبورد: `↑`/`↓` بین نتایج، `Enter` انتخاب، `Esc` بستن — همراه با نقش‌های ARIA
- `index.html?q=چراغ` صفحه را با نتیجه‌ی باز نمایش می‌دهد (برای لینک‌دهی و تست)

## هیروی سه‌بعدی

OpenRouter هیچ مدل تولید ویدیو ندارد، پس به‌جای یک کلیپ تخت، خودِ صحنه به لایه‌های عمق
تجزیه شده و یک دوربین پرسپکتیو واقعی میانشان حرکت می‌کند:

| لایه | عمق | توضیح |
|---|---|---|
| `.hero__plate` | ‎-۹۰۰px | پس‌زمینه بدون خودرو |
| `.hero__mist` | ‎-۴۶۰px | مه، با درفت آهسته CSS |
| `.hero__car` | ‎-۱۴۰px | خودروی جداشده + بازتابش |
| `.hero__fore` | ‎+۱۵۰px | کف خیس نزدیک دوربین |

هر لایه به نسبت `perspective/(perspective+depth)` از پیش بزرگ/کوچک شده تا قاب را پر کند.
چون عمق‌ها واقعی‌اند، یک چرخش دوربین پارالاکس واقعی می‌سازد — نه جابه‌جایی جعلی هر لایه.
دوربین سه ورودی دارد: نفس کشیدن آهسته‌ی خودکار، دنبال‌کردن ماوس، و پاسخ به اسکرول.

`assets/js/hero-fx.js` روی همین بخش یک بوم هم می‌گذارد و در همان حلقه‌ی `rAF` اجرا می‌کند:

| جلوه | توضیح |
|---|---|
| باران | سه لایه‌ی عمق با سرعت، طول و شفافیت متفاوت، با شیب باد |
| پاشش | قطره‌های لایه‌ی نزدیک روی خط زمین می‌ترکند |
| دود اگزوز | ستون دود از عقب خودرو، با صعود، پخش و تلاطم جانبی |
| بازتاب کف خیس | لکه‌های نور کشیده و نوسان‌دار در پایین کادر |
| رعد و برق | هر ۷ تا ۱۶ ثانیه یک پلک دوتایی |
| حرکت قاب | دوربین پرسپکتیو روی چهار لایه‌ی عمق |

تنظیم شدت از ثابت‌های بالای فایل: `WIND`، `GROUND`، `EXHAUST_X/Y` و آرایه‌ی `LAYERS`.

حلقه با `IntersectionObserver` بیرون از دید و با `visibilitychange` در تب پنهان متوقف
می‌شود، و در `prefers-reduced-motion: reduce` اصلاً اجرا نمی‌شود و تصویر ثابت می‌ماند.


## تصاویر تولیدشده با هوش مصنوعی

هیرو، ده عکس محصول و همه‌ی تصاویر صحنه با مدل‌های تصویری گوگل از طریق OpenRouter ساخته
شده‌اند تا کل سایت یک زبان بصری واحد داشته باشد: گرید آبی-مشکی عمیق، نور لبه‌ی سرد و
سطوح خیسِ بازتابنده.

```bash
cd tools
python gen_hero.py explore                     # چند طرح روی مدل ارزان
python gen_hero.py shoot rain <model> _wide 2K  # نسخه نهایی روی مدل قوی
python gen_layers.py plate                      # حذف خودرو -> پلیت + لایه خودرو
python gen_products.py                          # ده عکس محصول
python gen_scenes.py                            # بنرها، پس‌زمینه جستجو، مجله
python gen_hero.py spend                        # گزارش هزینه
```

کلید API در پوشه‌ی موقت جلسه نگهداری می‌شود، نه داخل مخزن. هر اجرا هزینه‌اش را در
`tools/_hero_gen/spend.json` ثبت می‌کند.

نکته‌ها:
- `image_config: {"aspect_ratio": "21:9"}` در فهرست پارامترهای رسمی نیست ولی OpenRouter
  آن را به گوگل پاس می‌دهد. سقف خروجی ۱۵۸۴×۶۷۲ است؛ `image_size: "4K"` بزرگ‌ترش نمی‌کند
  و فقط گران‌تر تمام می‌شود.
- `4K` روی `gemini-3-pro-image` خطا می‌دهد؛ فقط نسخه‌های `-preview` پشتیبانی می‌کنند.

## دستیار هوشمند عیب‌یابی

بخش `#diagnose` صفحه: کاربر خودرو و مشکل را شرح می‌دهد؛ دستیار علت‌های محتمل را با درصد احتمال
بررسی می‌کند، در هر مرحله ۱ تا ۳ سؤال دقیق با گزینه‌ی آماده می‌پرسد (حداکثر ۵ مرحله) و در پایان
**فقط از کاتالوگ فروشگاه** قطعه پیشنهاد می‌دهد. اگر قطعه‌ی مناسب نبود، به فرم «درخواست قطعه» ارجاع می‌دهد.
برای مشکلات ترمز، فرمان و داغ کردن موتور هشدار ایمنی نشان داده می‌شود.

| بخش | فایل |
|---|---|
| رابط کاربری | `assets/js/ai.js` و بلوک «AI diagnosis» در `assets/css/style.css` |
| کاتالوگ مشترک | `assets/data/catalog.js` — صفحه و سرور هر دو همین فایل را می‌خوانند |
| API | `server/index.js` — Node 18+ بدون هیچ وابستگی |

- **مدل:** `google/gemini-2.5-flash` از OpenRouter با خروجی JSON Schema سخت. در آزمون سه سناریو
  (لرزش ترمز، استارت ضعیف با قطعه‌ی خارج از کاتالوگ، تلاش برای تزریق دستور) در برابر
  Gemini 3.1 Flash Lite و GPT-4.1 mini بهترین سؤال‌ها و رفتار ایمنی را داشت.
- **امنیت کلید:** کلید OpenRouter فقط متغیر محیطی سرور است و هیچ‌وقت به مرورگر نمی‌رسد.
- **محافظ‌ها:** سقف درخواست هر IP در ساعت (`PER_IP_HOURLY`، پیش‌فرض ۲۰)، سقف روزانه‌ی کل
  (`DAILY_CAP`، پیش‌فرض ۱۵۰)، سقف طول متن و تعداد مرحله، CORS محدود به دامنه‌ی سایت، حذف
  شناسه‌های خارج از کاتالوگ و پیشنهادهای با اطمینان زیر ۳۵٪، و escape همه‌ی متن‌های مدل پیش از نمایش.
- **کف موجودی:** پیش از هر تحلیل، موجودی حساب OpenRouter (با کش یک‌دقیقه‌ای) خوانده می‌شود و اگر کمتر از `MIN_BALANCE` (پیش‌فرض ۰٫۳۰ دلار) باشد، مدل صدا زده نمی‌شود. چون عدد از خود OpenRouter می‌آید، با خوابیدن و ری‌استارت سرور صفر نمی‌شود. کلید فعلی دسترسی مدیریت کلید ندارد، پس سقف روی خود کلید فقط از داشبورد OpenRouter قابل تنظیم است.
- **هزینه:** حدود ۰٫۰۰۱۵ تا ۰٫۰۰۲ دلار برای هر مرحله (یک تشخیص کامل دو‌مرحله‌ای ≈ ۰٫۰۰۴ دلار).
- **پلن رایگان Render:** سرویس API بعد از ۱۵ دقیقه بی‌کاری می‌خوابد و اولین درخواست تا حدود یک دقیقه
  طول می‌کشد. صفحه وقتی کاربر به بخش دستیار نزدیک می‌شود `/health` را صدا می‌زند تا سرور زودتر بیدار شود.

اجرای محلی:

```bash
OPENROUTER_API_KEY=... PORT=8792 HOST=127.0.0.1 node server/index.js
python -m http.server 8791 --bind 127.0.0.1
# روی localhost صفحه خودکار به API پورت 8792 وصل می‌شود
```

آزمون خودکار روی localhost: `index.html?aisolo=1&aicar=پژو ۲۰۶&ai=متن مشکل&aiauto=1`
(`aiauto` تعداد مرحله‌هایی است که گزینه‌ی اول هر سؤال خودکار انتخاب و ارسال می‌شود).
